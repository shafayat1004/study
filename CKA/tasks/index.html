Exam quick-check

Before you mark any task done, run the highest-frequency checks. Wrong context, wrong namespace, and unverified output are the easiest ways to lose points.

Check Fast command or question Why it matters
Context kubectl config current-context Wrong cluster is the easiest way to lose points fast.
Namespace kubectl config view --minify -o jsonpath='{..namespace}' A correct object in the wrong namespace is still wrong.
Object exists kubectl get ... Do not trust an apply message alone.
Workload healthy kubectl describe ... and kubectl rollout status ... Events and rollout state reveal probe, image, and scheduling failures early.
Service path kubectl get svc,endpointslice Service issues are usually selector or port issues, not "network magic".
DNS works nslookup kubernetes.default.svc.cluster.local from a test Pod Fastest truth check for cluster DNS.
Node health kubectl get nodes The official troubleshooting flow starts here.
Logs checked kubectl logs ... and kubectl logs -p ... Current and previous logs solve most workload failures.
Metrics path kubectl top nodes If this fails, HPA-related assumptions may also be wrong.
Docs discipline Did I stay inside the allowed docs? CKA allows Kubernetes docs/blog, Helm docs, and Gateway API docs only.
Time control Am I stuck past ~8-10 minutes? Bank easy points first; partial progress beats thrashing.
